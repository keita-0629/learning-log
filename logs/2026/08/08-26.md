# 8/26 学習記録

## 学習内容

- VS Codeで発生したJavaプロジェクトのエラーを確認
- Problemsからエラー内容を確認
- Java Language ServerのWorkspaceをCleanしてエラーを解消
- VS Codeのエラー・警告・情報表示の違いを確認
- 行きたい場所アプリのPlaceクラスを使って仮データを作成
- ControllerからModelを使ってViewへデータを受け渡し
- Thymeleafを使ってPlaceの各項目を画面に表示
- Spring MVCの基本的な処理の流れを確認

## 学んだこと

- VS CodeではProblemsからプロジェクト内のエラー原因を確認できる
- Java Language Serverのキャッシュやビルド情報が原因でエラーが表示されることがある
- `Java: Clean Java Language Server Workspace` でJava関連のキャッシュを削除し、プロジェクトを再読み込みできる
- 赤色はエラー、黄色は警告として表示される
- Spring Bootの新しいpatch versionが存在する場合、警告として表示されることがある
- `Place place = new Place();` でPlaceクラスからオブジェクトを作成できる
- setterを使ってPlaceオブジェクトの各フィールドに値を設定できる
- Controllerの引数に `Model model` を指定すると、SpringがModelを用意して渡してくれる
- `model.addAttribute("place", place)` の `"place"` はView側で使用する名前、`place` は実際に渡すオブジェクト
- PlaceオブジェクトをModelに渡すことで、Thymeleaf側から各フィールドの値を利用できる
- Thymeleafでは `${place.name}` や `${place.prefecture}` のように、Modelに登録した名前からオブジェクトの値を取得できる
- MVCはModel・View・Controllerに役割を分ける考え方で、ControllerからModelを経由してViewへデータを渡す一連の流れとして理解した
- VS Codeでは `Shift + Alt + F` でコードを自動整形できる

## 苦戦したこと

- コード自体に問題がなくてもプロジェクトにエラー表示が出たため、最初は原因が分からなかった
- Problemsを確認することで、`application.properties` のビルド時の競合が原因だと特定できた
- `Model model` のModelオブジェクトがどこで生成されているのか混乱した
- `model.addAttribute("place", place)` の `"place"` と変数 `place` の違いが分かりにくかった
- Controller内で作成したローカル変数 `place` を使用できる範囲について確認した
- Thymeleafで値を取得するとき、`${place.prefecture}` のようにPlaceクラスのフィールド名を指定する必要があることを確認した
