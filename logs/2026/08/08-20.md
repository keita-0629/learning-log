- SQL の `UPDATE` について学習開始

## 学んだこと
- 削除処理の流れ
  - 詳細画面
  - POSTリクエスト
  - Controller
  - Service
  - Repository
  - DELETE SQL
  - DB
  - 一覧画面へリダイレクト
- `<form method="post">` でPOSTリクエストを送信できる
- `<button>` がボタン本体で、Bootstrap の `btn` は見た目を設定するクラス
- 編集画面では既存データを `findById()` で取得してフォームに表示する
- GETは編集画面の表示、POSTは編集内容の送信に使う
- `issueId` は「どの課題を編集するか」を表す
- `summary` と `description` は「どんな内容に編集するか」を表す
- SQLの役割
  - `INSERT`：データを追加
  - `DELETE`：データを削除
  - `UPDATE`：既存データを更新
- `data.sql` はテーブルではなく、初期データなどを記述するSQLファイル
- 今回使用しているテーブル名は `issues`

## 苦戦したこと
- Controller・Service・Repository のどこに処理を書くのか混乱した
- `data.sql` とDBのテーブルの役割が混ざった
- 初めて扱う `UPDATE` SQLの構造がまだ掴みきれていない
- 編集機能は複数の値を扱うため、削除機能より処理の流れが複雑に感じた
- 深夜で集中力が落ち、後半は新しい内容が入りづらかった
