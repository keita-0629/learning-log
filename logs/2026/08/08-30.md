# 8/30 学習記録

## 学習内容
- `Place.java → List<Place> → PlaceService → PlaceController → Model → Thymeleaf` の流れを復習した
- `model.addAttribute("places", places);` の左側と右側の役割を確認した
- `th:each="place : ${places}"` で、`place` が繰り返しの中で使う1件分の変数であることを確認した
- `PlaceRepository` の `@Select` からDBのデータを取得し、`/places` に「函館山」が表示されるところまで動作確認した
- `PlaceRepository` に `@Insert` と `addPlace(Place place)` を追加した
- `PlaceService` に `addPlace(Place place)` を追加し、RepositoryへPlaceを渡す処理を作った

## 学んだこと
- `model.addAttribute("places", places);` は、右側のJavaのデータを左側の名前でHTMLから使えるようにしている
- `th:each` の左側は事前に定義されたものではなく、繰り返しの中で1件分につける変数名
- `getAllPlaces()` はDBから複数のPlaceを取得し、`addPlace()` は新しいPlaceを1件追加する処理
- Repositoryでは `@Select` で取得、`@Insert` で追加のSQLを実行できる
- `placeRepository.addPlace(place);` では、Serviceが受け取ったPlaceをRepositoryへ渡している
- 一覧表示では `DB → Repository → Service → Controller → Model → HTML` の流れが実際につながっている

## 苦戦したこと
- `model.addAttribute()` の左右の役割を何度か混同した
- `th:each` の `place` とEntityの `Place` の違いが混ざった
- SQLの `INSERT INTO`、列名、`VALUES` の関係がまだ曖昧だった
- RepositoryとServiceの役割が混ざり、Serviceに書く処理を一度Repository側に書いてしまった
