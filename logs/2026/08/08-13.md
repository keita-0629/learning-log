# 8/13 学習記録

## 学習内容
- Spring Boot 課題管理アプリの続きを実装
- `IssueRepository` / `IssueService` / `IssueController` の処理の流れを復習
- `IssueForm` を作成し、フォームから送信された値を受け取る処理を実装
- `@PostMapping` を使ったPOSTリクエストの受け取り
- MyBatisの `@Insert` を使ったDBへの課題登録
- `@Transactional` とロールバックの動作を確認
- リダイレクトによる二重サブミット対策（POST → Redirect → GET）
- Validationの依存関係を追加
- `@Validated` / `BindingResult` を使った入力チェック
- Thymeleafでバリデーションエラーを画面に表示
- ブレークポイントを使い、フォームの入力値が `IssueForm` に渡っていることを確認
- HTML / Thymeleafの記述ミスによるエラーを修正

## 学んだこと
- `IssueEntity` はDBの1件分のデータを扱うための器、`IssueForm` は画面から入力された値を受け取るための器
- `List<IssueEntity>` は複数行のIssueデータをまとめて扱う
- `Service` はRepositoryを呼び出し、実際のSQLによるDB操作はRepositoryが担当する
- `model.addAttribute()` を使うことでControllerからHTMLへデータを渡せる
- `th:each` はリストから1件ずつデータを取り出して繰り返し表示する
- `th:field="*{summary}"` などでHTMLの入力欄とFormのフィールドを結びつけられる
- `@PostMapping` はPOSTリクエストを受け取る
- `@Transactional` を付けた処理で例外が発生すると、DB操作をロールバックできる
- `redirect:/issues` ではブラウザが改めて `GET /issues` を送り、対応する `@GetMapping` が実行される
- `@Validated` で入力値を検証し、`BindingResult` で検証結果を受け取れる
- `bindingResult.hasErrors()` がtrueなら登録処理へ進まず、入力画面へ戻せる
- `th:errors` などを使ってValidationのエラーメッセージを画面に表示できる
- `if` 内で `return` すればそこでメソッドが終了するため、必ずしも `else` は必要ない

## 苦戦したこと
- Controller → Service → Repository → DB の役割分担がまだ曖昧になることがあった
- `redirect:/issues` からなぜ `showList()` が実行されるのか理解するのに苦戦した
- `IssueForm` と `IssueEntity` をなぜ分けるのか、設計上の基準がまだ曖昧
- HTMLの `<form>` を分けてしまい、POSTが正しく送信されなかった
- `th:field` や `method` などのスペルミスでエラーが発生した
- Spring Bootのプロセスが残っており、8080番ポートが使用中になる問題が発生した
- 動画を細かく止めながら理解しようとしていたため、講座の進行に時間がかかった
