# 8/18 学習記録

## 学習内容
- Spring Boot 課題管理アプリの全体の処理を軽く復習
- 一覧表示の Controller → Service → Repository → DB → View の流れを確認
- 新規登録時の `@Validated` / `BindingResult` / `IssueForm` の役割を復習
- 課題管理アプリの改造を開始
- 新機能として「課題削除機能」の実装に着手
- Repository に `@Delete` と `deleteById()` を追加
- Service に削除処理を追加
- Controller に削除用の POST 処理を追加
- `@PathVariable` を使って URL から課題 ID を受け取る処理を確認

## 学んだこと
- `IssueEntity` は DB から取得した課題データを表し、`Model` は Controller から HTML へデータを渡すために使う
- `BindingResult` にはバリデーションの結果やエラー情報が入る
- `findAll()` はデータの取得、`insert()` は登録、`deleteById()` は削除という役割の違い
- `return "issues/List"` は表示する HTML の指定で、`return "redirect:/issues"` は URL へのリダイレクト
- MyBatis では `@Select` / `@Insert` / `@Delete` などを使って、Repository のメソッドと SQL を対応させられる
- `@PathVariable` を使うと、`/issues/27` のような URL に含まれる値を Java の変数として受け取れる
- `"issueId"` は文字列だが、`@PathVariable("issueId")` では URL 上の変数名を指定するための文字列として使われている
- DB 操作を追加するときは、Repository → Service → Controller → HTML の順で組み立てると処理を追いやすい

## 苦戦したこと
- `IssueEntity` と `Model` の役割が少し混ざった
- `BindingResult` の役割を思い出すのに苦戦した
- Repository の取得処理と登録・削除処理の違いで混乱した
- `@PathVariable` の役割や書き方を忘れていた
- Java の変数 `issueId` と文字列 `"issueId"` の違いで迷った
- Thymeleaf で動的な URL を組み立てる部分はまだ慣れていない
