## 学んだこと

- `Place` は場所1件分のデータを表し、`List<Place>` は複数のPlaceをまとめて扱う
- Service側とController側で同じ `places` という名前を使っていても、別の変数として扱われる
- `return` で返されるのは変数名ではなく、その変数に入っている値
- `model.addAttribute("places", places)` の `"places"` はView側で使う名前、右側の `places` は実際に渡すデータ
- `th:each` はJavaの拡張for文のように、Listの中から1件ずつデータを取り出して繰り返し表示する
- アプリがデータを取りに行く流れは `Controller → Service → Repository → DB`
- DBから取得したデータは `DB → Repository → Service → Controller → Model → Thymeleaf` の順で画面まで戻ってくる
- RepositoryはServiceとDBの間に入り、DBとのやり取りを担当する
- `@Select("SELECT * FROM places")` を使うことで、`places` テーブルのデータをすべて取得できる
- `List<Place> getAllPlaces();` は複数のPlaceを取得して返すメソッドとして使える
- `schema.sql` はDBのテーブルを作るためのファイル
- `data.sql` は作成したテーブルに初期データを入れるためのファイル
- コンストラクタは、そのクラスのオブジェクトが作られるときに呼ばれる
- Springでは `@Service` などが付いたクラスをSpring側が用意してくれるため、自分で `new` を書いていなくてもコンストラクタが呼ばれる
- `this.placeRepository = placeRepository;` は、コンストラクタで受け取ったRepositoryをService自身が持つ変数に保存している
- 実装する順番と、アプリが実際に動く順番は別なので、処理の流れを意識しながらコードを見ることが大切

## 苦戦したこと

- コンストラクタ注入の形は何をしているか理解できたが、まだ自力ですぐ書けるほど定着していない
- Service、Repository、DBを追加する途中で、実装する順番が前後して処理の流れが分かりにくくなった
- `PlaceController` のコンストラクタ引数を `placeSerivice` とスペルミスしていたため、`placeService` が初期化されていないというコンパイルエラーが発生した
- VS Code上の表示だけでは原因が分からなかったため、Mavenのコンパイル結果を確認して原因を切り分けた
- 保存前のコードと実際にMavenが読み込んでいるコードの違いを確認するために `Get-Content` を使用した
- VS CodeからSpring Bootを起動する際に問題が発生したが、プロジェクトフォルダを正しく開き直して起動できた
