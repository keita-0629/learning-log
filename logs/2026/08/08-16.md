# 8/16 学習記録

## 学習内容
- Spring Boot 課題管理アプリのコードを `main()` から順番に読み直し
- `Controller → Service → Repository → DB` の処理の流れを確認
- DBから取得したデータが `Model → Thymeleaf → HTML` に戻る流れを確認
- DIとLombok（`@RequiredArgsConstructor`）の役割を整理
- `schema.sql` / `data.sql` / `issues` テーブルの関係を確認
- `@ModelAttribute` と `IssueForm` を使ったフォーム表示まで確認
- 新規作成フォームから `POST /issues` が送信されるところまで確認

## 学んだこと
- Lombokはコンストラクタを生成し、Springが必要なインスタンスをDIする
- `schema.sql`でテーブルを作成し、`data.sql`の`INSERT`で初期データを登録する
- Repositoryで取得した`List<IssueEntity>`がService、Controllerへ返される
- `Model`はControllerからHTMLへデータを渡すために使う
- `model.addAttribute()`で登録した名前をThymeleafの`${...}`から参照できる
- `@ModelAttribute`を使うことで`IssueForm`をModel経由でHTMLから利用できる
- `th:object`と`th:field`でフォームと`IssueForm`を結びつけられる

## 苦戦したこと
- DIで「何が必要かをSpringがどう判断しているのか」の理解
- LombokとDIの役割の違い
- `schema.sql`と`data.sql`、実際のDBテーブルの関係
- Modelや`IssueForm`など、クラス・変数・インスタンスの区別
