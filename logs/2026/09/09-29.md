# 9/29 学習記録

## 学習内容
- Gitでdaycare-scheduleのリポジトリを初期化
- 最初のコミットを作成
- GitHub DesktopからGitHubへPrivateリポジトリとして公開
- コミットとGitHubへの同期の流れを確認
- 保護者側の利用時間入力欄を削除
- Controller側の不要なstartTime・endTimeの受け取り処理を削除

## 学んだこと
- コミットはコードの変更履歴を残す「セーブポイント」のようなもの
- ローカルでコミットしただけではGitHubには反映されず、Push・同期が必要
- 今後は「1機能・1修正・1仕様変更」を目安にコミットする
- HTMLからinputを削除した場合、Controller側でその値を@RequestParamで受け取っていないかも確認する必要がある
- 必須の@RequestParamに対応する値がフォームから送られないと、POST時にエラーになる可能性がある

## 苦戦
- Gitの初期設定、GitHubとの接続、ローカルコミットとGitHubへの反映の違いが最初は分かりづらかった
- VS Codeの「Branchの発行」がうまくいかなかったため、GitHub Desktopからリポジトリを公開した
- 利用時間の入力欄はHTMLを消すだけでよいと思ったが、Controller側にも関連処理があることを確認した

## 次回
- 再開時メモを確認してから開発を再開する
- 職員側で設定した曜日ごとの基本利用時間を、選択した日付に応じて保護者側へ表示する仕様を進める
- 保護者側では利用時間を変更不可とし、変更希望がある場合は備考欄に記入する形で進める
- 意味のある変更が1つ完成するごとにコミットする
