# 9/16 学習記録

## 学習内容
- daycare-scheduleアプリの全体設計を整理
- 保護者画面・職員画面で必要な機能を確認
- `/guardian` にアクセスしたときの画面表示を実装
- `GuardianController` から `Model` を使ってViewへ値を渡す処理を確認
- `home.html` の `th:text` を使って、画面に保護者名を表示

### daycare-scheduleの設計
- 保護者（GUARDIAN）と職員（STAFF）の2種類のユーザーを想定
- ログイン機能は最終的に必ず実装するが、まずは利用予定管理の本体を作る
- 職員側で以下の情報を登録・編集できるようにする
  - 保護者情報
  - 児童情報
  - 契約曜日
  - 月の契約日数
- 保護者画面では以下を表示する
  - 児童名
  - 契約曜日
  - 月の契約日数
  - 今月の利用希望日数
  - 残り申請可能日数
  - 月間カレンダー
- 月の契約日数を超える利用希望は登録できないようにする
- 契約日数の上限判定は画面だけではなくService層でも行う
- 保護者はカレンダーから日付を選んで利用希望を登録する
- 利用希望ごとに以下の情報を持たせる
  - 利用日
  - 送迎先（学校 / 自宅）
  - 備考
- 送迎先と備考は児童の固定情報ではなく、その日の利用希望に紐づける
- 職員側では月間カレンダーに日ごとの利用予定人数を表示する
- 日付を選択すると、その日の利用児童・送迎先・備考を確認できるようにする
- データはアプリ再起動後も消えない永続化設計にする
- 本体完成後、余裕があればイベント機能を追加する
- 見た目は白ベース・淡い青や緑・角丸を使った「やさしい業務アプリ」を目指す

## 学んだこと
- `model.addAttribute("guardianName", "田中太郎");` のように、ControllerからViewへ値を渡せる
- `guardianName` はView側から値を取り出すための名前
- `田中太郎` は実際に渡している値
- HTML側では `${guardianName}` のようにControllerで設定した名前を指定する
- Controller側とView側で名前が一致していないと値は正しく表示されない
- `/guardian`
  → `GuardianController`
  → `Model`
  → `home.html`
  → ブラウザ表示
  という流れを確認できた
- 契約日数の上限チェックのような業務ルールは、Service層で扱う方針にする
- 送迎先や備考のように日によって変わる情報は、その日の利用希望に持たせる考え方を確認した

## 苦戦
- `model.addAttribute()` の名前を最初すぐには思い出せなかった
- ControllerからViewへ値がどう渡っているのかを整理する必要があった
- `guardianName` と実際の値である `田中太郎` の役割の違いを確認した
- アプリに入れたい機能が増えてきたため、本体機能と追加機能を分けて整理した
