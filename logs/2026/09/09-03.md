# 9/3 学習記録

## 学習内容
- GETとPOSTの違いを復習
- `@GetMapping` と `@PostMapping` が「URL + HTTPメソッド」で処理を分けていることを確認
- `@Valid Place place`、`BindingResult`、`Model` の役割を復習
- `Place` 1件と `List<Place>` 複数件の違いを整理
- `Controller → Service → Repository → DB` のデータ取得・処理の流れを確認
- 削除機能の実装を開始
- `Place` に `id` フィールドを追加
- 一覧画面に削除フォームを追加
- `@PathVariable` を使ってURL内のidをControllerで受け取る処理を追加
- ControllerからServiceへ削除対象のidを渡す処理を追加
- ServiceからRepositoryへ削除対象のidを渡す処理を追加
- MyBatisの`@Delete`とDELETE文の書き方を学習

## 学んだこと
- GETは主に情報取得、POSTは主にデータ送信に使う
- 同じ`/places`でもGETかPOSTかによって動くControllerメソッドが変わる
- URL直打ちは基本GETとして送信される
- `@Valid`は入力チェック、`BindingResult`はチェック結果、`Model`はHTMLに渡すデータの箱
- `Place`は複数フィールドを持つ1件分のデータで、`List<Place>`はそのPlaceが複数入ったもの
- データ取得はControllerが直接DBへアクセスするのではなく、ServiceとRepositoryを経由する
- メソッドを定義するときは引数に型を書くが、メソッドを呼び出すときは値だけ渡す
- `@PathVariable`はURLの`{id}`部分の値をJava側で受け取るために使う
- MyBatisのSQLはJavaの文字列として書くため、短いSQLは`"`、複数行は`"""`で囲む
- `DELETE FROM places WHERE id = #{id}`で指定したidのデータだけを削除できる
- 削除後はHTMLを直接返すより`redirect:/places`で一覧取得処理を再実行する方が自然

## 苦戦したこと
- GETとPOSTの「送る側・受け取る側」の関係が混乱した
- `Place`が1件という意味と、1件の中に複数フィールドがあることの整理
- `BindingResult`と`Model`がどちらも箱に見えて役割が混同した
- メソッド定義時と呼び出し時で型を書く場所の違い
- Thymeleafの削除フォームを`th:each`の外に置いてしまった
- `@Delete`の中にSQLを文字列として書く必要がある点
- SQLは読めば意味は分かるが、自分で書くことにはまだ慣れていない
